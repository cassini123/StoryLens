# 第二部分：这些字段对应论文什么概念

## 2.1 研究问题（唯一 IV 叙事）

论文不问「Sketch 会不会让图更好」。

问的是：T2 那套**临时视觉脚手架**（操作草图 → 系统把场景说成话 P_auto → 人改写成 P_user）能不能让人在自然语言里**更精确地表达想改的视觉内容**。

生成永远是：当前图 + 被试自己的字。草图只是认知支架，不是图像条件。

## 2.2 设计：组、阶段、块

| JSON / 表字段 | 论文概念 | 用法 |
| --- | --- | --- |
| `group` 1 / 0，`experimental_group` scaffold / control | 组间自变量 | 不要用 `task_id` 反推组别 |
| `assignment_pattern` A/B/C | 刺激分层旋转 | 平衡图库，不是自变量 |
| `condition_order` | 7 题阶段序列 | 脚手架 T0>T1>T1>T2>T2>T3>T3；控制 T0>T1×4>T3×2 |
| `block=baseline`（T0） | 基线描述，无 AI | 不进 Primary；看语言起点 |
| `block=early`（前两道 T1） | 纯文本+生成 的共同前测 | Primary 的减数 |
| `block=middle`（T2 或 T1′） | 处理 vs 等时练习控制 | Primary 的被减数。控制组多练的是 T1，不是 T2 |
| `block=transfer`（T3） | 拿掉脚手架后的近迁移 | Transfer = 脚手架 T3 − 控制 T3。不是长期学习 |
| T2 三开关 Sketch+Auto+AI | 脚手架操作化 | 控制组 middle 必须没有这些 |

**禁止**用「T2 分 > T1 分」声称脚手架有效：缺少练习控制。

```text
Primary  = (脚手架 middle − 脚手架 early) − (控制 middle − 控制 early)
Transfer = 脚手架 T3 − 控制 T3
```

## 2.3 精度：主 DV 还没有

| 字段 | 论文概念 | 这 11 包 |
| --- | --- | --- |
| `target_modification_specification` | 研究者隐藏目标（spatial/camera/relation/object…） | 有，供编码；T0 应为 null |
| 专家 0–3 标准 | 可执行精度，不是专业词 | **未做** |
| `P_i` / `P_norm` / `delta_P` | 主跨题指标；P_norm = P_i / (3 × 活跃标准数) | **全空** |
| `expert_ratings.csv` | 正式评分表 | 空文件 |
| `text_versions` 的 `final` | 被评分的语言产物 | 有，可编码 |
| `generations.input_text` | 模型实际吃到的字（应=被试终稿） | 有；P004 T2-1 终稿缩短但 API 仍是初稿，编码要以 **送进 API 的字** 还是 **任务表终稿** 预先规定 |

没有 P_norm，就不能在 Results 写脚手架提高（或降低）了表达精度。

## 2.4 脚手架机制（中介过程，不是 DV）

```text
当前图 → 人写 P_user
      → 生成反馈
      →（仅 T2）改 Sketch
      → Interpret → P_auto
      → 人改写 P_user
      → 生成(当前图, P_user)     Sketch 不进 API
```

| 字段 | 概念 |
| --- | --- |
| `sketch_interactions` / snapshots `kind=initial, pre_auto_prompt, post_user_revision` | 支架操作过程 |
| `auto_prompts.auto_prompt` / `p_auto` | Sketch-to-language |
| `user_prompt_after` / `p_user` / `user_revised` | 人重新表达 |
| `copy_ratio` / `copied_segments` | 从 Auto 粘了多少。允许复制；**不是**学没学会；**不自动剔除** |
| `sketch_sent`、`api_input`、`input_sketch_snapshot_id` | 分离假设。11 包全部成立 |
| `generation_input_chain_valid` | 第 2 轮是否吃上一张生成图。失败轮会断，不等于场次作废 |

## 2.5 次级与成本（可报，不能冒充精度）

| 字段 | 概念 | 注意 |
| --- | --- | --- |
| `self_alignment_rating` | 我认为自己说清了（1–7） | 天花板；≠ P_norm |
| `result_alignment_rating` | 图像不像我想的 | 测的是生成质量感知，**不是**研究问题 |
| `total_task_time_ms` | 墙钟，交互成本 | 离开座位会炸；用中位数 / 剔离席 |
| `text_edit_time_ms` / `sketch_edit_time_ms` / `generation_wait_time_ms` | 写、画、等模型 | 等待不是认知 |
| `satisfied_round` / `number_of_rounds` | 停轮 | T2 被协议逼着走完 loop；并发失败会虚增轮次 |
| 字数 | 探索性产量 | 长 ≠ 可执行 |

正式 n=9 上自评 Primary 为负（脚手架 middle 相对 early 的涨幅小于控制），Transfer≈0。这只说明 Likert 上没有脚手架优势，**不能**写成「脚手架无效」。

## 2.6 场次质量（进不进效力表）

| 字段 | 概念 |
| --- | --- |
| `completion_status=complete` 且 7 题 `ended_at` | 做完 |
| `export_ready` + `validation.flags` 全过 | 协议完整，才能进正式效力 |
| `session_recovery` / resume events | 刷新后续上同一 `session_id`，事件只追加 |
| 不完整场 | 不是效力样本，只做恢复检查 |

# 第三部分：有效吗、噪声怎么去、后面怎么改、哪几包有问题

## 3.1 结论先说

- **过程数据有效**：11 场独立、组分配对、草图未进 API、T2 loop 形态在、文字链可编码。  
- **效力结论还不能写**：主 DV（P_norm）不存在。  
- **正式效力表用 n=9**（去掉 P003、P004）。其余问题当**噪声/协变量/敏感度**，不要整包扔掉——除非协议本身不合格。

不要做的事：高 copy 剔除；用墙钟均值；把失败重试算成「多轮 refinement」；用 result_alignment 当精度；T2>T1 当主结果。

## 3.2 哪几包有问题（分级）

### A. 不进正式效力（协议级）

| --- | --- | --- |

| **P004** | v1；缺 event_log、validation、session_recovery；T0 仍有 target | 只作 v1 过程参考。以后禁止 v1 进 between-v2 表 |

### C. 过程最干净（仍无 P_norm）

**P005、P006、P010**（P005 自评贴天花板，编码时仍可能很粗）。**P008** 接近干净。

### D. 不是数据坏，是日志坏

5 包填写 ID=P001。论文表用 **P001zip–P011zip** 或事后匿名码。不要按填写 ID merge。

## 3.3 噪声清单与去除规则

按协议能扔的只有「不完整 / 非 v2 / 未 export_ready」。其余分层处理：

| 噪声 | 来源 | 效力样本 | 精度（将来 P_norm） | 时间 |
| --- | --- | --- | --- | --- |
| 填写 ID 撞车 | 登录名 | 用 zip 标签 | 同左 | 同左 |
| 并发 Limit | 叠场 + 当时无重试 | **不剔人** | 只编码成功终稿 | 失败等待可从成本里分开 |
| 文本风控 | P002 两轮 | 不剔人 | 该轮作废，用后来通过的终稿 | 该轮等待可标异常 |
| 墙钟离席 | 等待短、墙钟以小时计 | 不剔人 | 不影响文字 | **该题时间删除或 30 min 缩尾**；报告中位数 |
| 刷新续场 | 设计允许 | 不剔；append-only 正常 | 同左 | visibility_hidden 可辅助标离席 |
| 高 copy Auto | P003 一道 =1 | **不剔**（协议） | 照常编码终稿可执行性 | — |
| 不用 Auto | P001/P010 等 | 不剔（处理暴露仍成立） | 这正是机制：暴露≠采纳 | — |
| Likert 天花板 | 多人 6–7 | 不剔 | 自评不当主 DV | — |
| 无专家分 | 还没编码 | 不能报 Primary 精度 | 先编码再跑同一公式 | — |

**推荐分析集：**

1. 正式效力：n=9，v2 + export_ready + 7 题结束  
2. 敏感度 A：n=11，全部做完  
3. 时间：n=9，但题级丢掉墙钟≥30 min 且等待正常的题（P002 T1′、P007 T1、P009 T2、P011 T2）  
4. 精度：编码全部 n=11 终稿，主分析锁 n=9，附录 n=11  

并发失败轮：`success=false` 的 generation **不是**一次有效视觉反馈，satisfied_round / round 计数要减掉失败或另列 `n_successful_rounds`。

## 3.4 之后实验怎么优化（按优先级）

**已经能立刻做、不改实验故事**

1. 专家按 0–3 **可执行**标准编码 `final`（和/或 `generations` 最后一次成功 `input_text`）。专业词不能给 3。  
2. 被试 ID 改成必填唯一（或系统发 P012、P013…），禁止默认 P001。  
3. 正式表写死：v2 + export_ready + 7×ended；P003/P004 附录。  
4. 时间用 log(墙钟) 或中位数，并列 sketch 时间、等待、写字。  
5. Limitations 写：并发上限、风控、Likert、n 小、T2 更贵。

**系统上（有的已在后来的修复里）**

6. 生成 429/5xx 自动重试，失败不消耗轮次、不把当前图换成卡死灰图——减少 P001/P009/P011 那种噪声。  
7. 计时 start/end 必须成对，否则不能点完成（针对 P003）。  
8. 长时间 `visibility_hidden` 在导出里打 `away_from_task`，时间模型自动排除。  
9. 同时在线人数 / 队列，避免两场脚手架 08:11 撞车。  
10. T2 若 Auto 从未被看或 copy+改写都为空，不要拦完成，但 flag `scaffold_not_uptake` 供机制分析。

**设计与现场**

11. 口头强调：不要把标签页挂去吃饭；刷新可续，离开请点暂停。  
12. T0 写太短（如 P003）可设最短观察时间，避免赶场。  
13. 控制组 middle 已经是 T1′，不要再加别的工具。  
14. 样本量：现在正式 S4/C4 量级，只够描述。P_norm 有了再看效应方向；推断要另算。  
15. 收 P012 及之后，保持 v2，不要混 v1 zip。
